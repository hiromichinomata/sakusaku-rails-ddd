# うめチケット コンテキストマップ

```text
              ┌──────────────────────┐
              │ イベント管理（支援）   │  告知としてのイベント
              │ EventManagement      │  タイトル・説明・会場・日時・定員・料金
              └──────────┬───────────┘
                         │ 上流（U）: イベントの開始日時・定員・料金を渡す
                         │ 下流（D）: 予約は、自分の言葉（残席・受付期間・返金期限）に読み替える
                         ▼
              ┌──────────────────────┐
              │ 予約（コア）          │  販売の対象としてのイベント（残席）と予約
              │ Ticketing            │  仮予約・確定・キャンセル・期限切れ
              └───┬──────────────┬───┘
                  │              │ 予約で起きたこと（予約された・確定した・キャンセルされた）を知らせる
                  │              ▼
                  │   ┌──────────────────────┐
                  │   │ 通知（汎用）          │  メールの宛先・件名・本文
                  │   │ Notification         │
                  │   └──────────────────────┘
                  │ 支払い・返金を頼む（金額と支払いIDだけを渡す）
                  ▼
              ┌──────────────────────┐        ┌──────────────────────┐
              │ 決済（汎用）          │───────▶│ うめペイ（外部）      │
              │ Billing              │ 腐敗防止層 │ charge・refund の API │
              └──────────────────────┘        └──────────────────────┘
```

| 関係 | 上流 → 下流 | パターン | 決めたこと |
|------|-----------|---------|-----------|
| イベント管理 → 予約 | イベント管理が上流 | 顧客／供給者 | 予約は、イベントの開始日時・定員・料金だけを受け取り、自分のモデルに読み替える |
| 予約 → 通知 | 予約が上流 | 公開された言語（ドメインイベント） | 通知は、予約で起きたことを受け取ってメールを送る。予約は通知のことを知らない |
| 予約 → 決済 | 決済が上流 | 顧客／供給者 | 予約は、金額と支払いIDだけで決済に頼む。決済は予約のルールを知らない |
| 決済 → うめペイ | うめペイが上流 | 腐敗防止層 | うめペイの言葉（charge・token）を `Billing` の中に閉じ込める |

## コードの境界（第6章の時点）

| コンテキスト | Ruby のモジュール | 今あるコード |
|-------------|-----------------|------------|
| イベント管理 | なし（Rails の標準の場所） | `Event`・`EventsController` |
| 予約 | `Ticketing`（第8章から） | `Reservation`・`ReservationsController`・`PaymentsController` の判断 |
| 決済 | `Billing` | `Billing::PaymentGateway`・`Payment` |
| 通知 | `Notification`（第12章から） | `ReservationMailer` |

# 0001 抽選を、残席とは別の集約にする

- 状態: 採用（第21章）
- 決めた人: 初花・マリゴールド

## 背景

人気のイベントで、発売開始の瞬間に申込が集中し、残席の行のロックを取り合う（第16章の one more thing）。主催者から「公平に選びたい」という要望があった。

## 決めたこと

抽選の申込（`lottery_entries`）を、残席（`Inventory`）とは別に持つ。申込の時点では席を押さえず、抽選（`Ticketing::DrawLottery`）の1回のトランザクションの中で、当選者の席をまとめて押さえる。抽選の判断は `Ticketing::Lottery`（乱数を外から受け取る PORO）に置く。

## ほかに考えた案

| 案 | 選ばなかった理由 |
|----|----------------|
| 申込の時点で仮予約を作り、落選者をキャンセルにする | 落選者の席が一時的に押さえられ、キャンセルとして記録が残る。キャンセルのメールや返金の判断が誤って動く |
| 残席の集約に、抽選の申込の一覧を持たせる | 第9章の案Aと同じで、集約が大きくなる |

## 結果

- 先着と抽選は、残席の `sales_method` で分ける。抽選のイベントには先着の申込をさせない（`Inventory#ensure_first_come!`）
- 当選者への仮予約は、キャンセル待ちと同じ `Ticketing::AllocateSeats` で作る
- 当選者の支払い期限は、先着と同じ15分のまま。長くするなら、予約に支払い期限を持たせる必要がある（演習）
